- Repo name:         crypto-lab-kmac-gate
- Short name (H1):   KMAC Gate
- Subtitle:          Keyed Keccak · SP 800-185 / FIPS 202
- One-liner:         SHAKE, cSHAKE, and KMAC built on one Keccak-f[1600] sponge — the same permutation doing hash, XOF, domain-separated XOF, and keyed MAC.
- Concept to teach:  One sponge, four modes: hashing, extendable output, domain separation, and keying are all the same Keccak permutation with different framing — and keying it (KMAC) needs no HMAC wrapper because the sponge's capacity already resists length extension.
- Primitives/spec:   FIPS 202 (SHA3-256, SHAKE128/256); SP 800-185 (cSHAKE128/256, KMAC128/256, KMACXOF128/256, incl. bytepad / left_encode / right_encode / encode_string). Official NIST CAVP + SP 800-185 sample vectors as KATs.
- Accent (--accent): #6E4CB8
- Favicon emoji:     🧽
- In scope:          One hand-rolled, inspectable Keccak-f[1600] permutation as the shared core, with every higher function built on it (the "same sponge" claim must be literally true in code — assert it by wiring all four modes through one permutation function, not four copies). Four progressively-disclosed stages on that one core:
                     (1) SHA3-256 — type a message, watch the sponge absorb the padded input and squeeze a 256-bit digest, with the rate/capacity split drawn.
                     (2) SHAKE128/256 — the same absorb, then squeeze arbitrary length via a draggable output-length control; show that longer output is a continuation of the same squeeze, not a rehash.
                     (3) cSHAKE128/256 — add editable function-name N and customization S; changing S yields an unrelated digest (show the divergence live), and empty-N/empty-S correctly falls back to plain SHAKE (show the byte-level equality that proves the fallback).
                     (4) KMAC128/256 + KMACXOF — add an editable key; sign a message, verify it, then tamper with the message and watch verification reject (the built-in break-it-yourself, §2, against the real primitive). Show output-length binding: KMAC of one message at two requested lengths gives unrelated outputs, not a truncation of one another.
                     Closing contrast exhibit (NOT the headline — one beat): a compact "why key it this way" panel placing KMAC beside a naive SHA-256(key‖message) MAC, noting that the Merkle–Damgård construction admits an append/length-extension forgery while the sponge does not.
